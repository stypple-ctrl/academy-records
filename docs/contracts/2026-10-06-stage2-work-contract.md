## 1. 목적

"학원이 우리 아이를 알고, 먼저 발견해서 챙기고, 성장시켰다"는 것을 **학부모가 실제로 받는 한 장**으로 보여준다.
지금까지는 교사용 데이터 묶음만 있었고, 학부모가 받는 모습을 체험할 수 없었다.

## 2. 작업 범위

### 2-1. 포함

| 번호 | 작업 | 내용 |
|---|---|---|
| **5-1** | 학부모 화면 | 폭 420px 모바일 카드 1장. 위에서부터 ① 학원명·학생 이름·"{M}월 성장 리포트" ② 담임 코멘트 ③ 단어 평균 꺾은선(최근 3개월) + "지난달보다 +N점" ④ "이번 달 이렇게 챙겼어요" 발견→조치→결과 카드 ⑤ 숙제 제출률·보충 학습 원형 게이지 ⑥ 대표작 전월·이번 달 나란히 |
| **5-2** | 승인 전 표시 | 담임 승인 전이면 맨 위에 "미리보기 · 담임 승인 전" 띠 |
| **5-3** | 학부모용 말투 | "나머지" 대신 "보충 학습". 케어 기록은 원본 문장 없이 학부모용 문장으로만 |
| **5-4** | 이동·인쇄 | 리포트 화면에 "학부모 화면 미리보기" 버튼. 미리보기에 "인쇄 / PDF 저장", "리포트로 돌아가기" |
| **5-5** | 권한 | 원장(전체)과 담임(자기 학생)만 열 수 있음. 조교·원어민 교사는 권한 없음 화면 |
| **보완 A** | 코멘트 공용화 | 리포트 화면과 학부모 화면이 같은 코멘트·선택 기록을 쓰도록 공용 함수 `commentOf(sid, month)`로 분리. 기본 선택 기록은 "개선" 또는 "긍정 변화" |
| **보완 B** | 부정 표현 경고 | 선생님이 직접 쓴 코멘트·대표작 코멘트에 부정어(엎드려, 잡담, 산만, 악화, 미제출, 미완, 장난, 부족, 하락)가 있으면 리포트 화면과 미리보기에 경고 표시. 글을 자동으로 고치지는 않음 |
| **보완 C** | 학원명 | 데이터에 없어 `ACADEMY_NAME = 'OO영어학원'` 한 곳에 두고 표시. 나중에 한 줄만 바꾸면 됨 |
| **보완 D** | 권한 점검 | 조교·원어민이 학부모 화면을 못 여는지 자동 점검 추가 |

### 2-2. 제외

- 실제 발송(문자·알림톡·이메일) — 원장 결정 대기 항목
- 리포트 발송 승인 흐름(담임 검토 → 원장 승인 → 발송) — 원장 결정 대기 항목
- 영상 재생, 에세이 원문 보기 — 대표작은 링크 "보기" 버튼까지만
- 1단계 발견 목록 중 보완 B 외 나머지
- 3단계 이후 작업 전부
- 진행 중 새로 발견한 문제 → 고치지 않고 발견 목록에 기록

### 4-2. 기존 기능 유지

- [ ] 1단계 회귀 6가지(조교 입력 → 담임 확정 → 조교 처리·이월 → 원장 경로 → 원어민 대표작 → 전 메뉴 오류 0건)

### 4-3. 원장 체험 확인

- [ ] 원장 → 월말 리포트 → 강서연 → "학부모 화면 미리보기"가 휴대폰 화면 한 장처럼 보인다
- [ ] 승인 전에는 "담임 승인 전" 띠가 있고, 승인하면 사라진다
- [ ] "이번 달 이렇게 챙겼어요" 카드에 원본 문장(예: "필기 안 하고…")이 없다
- [ ] 코멘트에 "부족"을 넣으면 경고가 뜬다
- [ ] "인쇄 / PDF 저장"을 누르면 카드만 인쇄된다

## 5. 작업 방식과 안전장치

- 점검 먼저 작성 → 실패 확인 → 구현 → 통과 확인 → git 저장.
- 새 화면 위주라 기존 기능 영향은 적지만, `reportPage`의 코멘트 생성 부분을 공용 함수로 옮기므로 리포트 화면을 회귀 점검에 넣음.
- 문제가 생기면 2단계 시작 지점(`2bd91a9`)으로 되돌릴 수 있음.
- 작업 후 별도 검토자 1회. 작업자가 스스로 승인하지 않음.
