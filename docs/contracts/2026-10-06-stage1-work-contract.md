## 1. 목적

체험 중 발견한 문제 가운데 **작고, 서로 영향을 주지 않으며, 바로 사고로 이어질 수 있는 것**을 먼저 고친다.
1단계가 끝나면 조교·교사의 입력 실수가 줄고, 학부모에게 나갈 리포트 초안에 부정적인 원본 문장이 들어가지 않는다.

### 2-2. 제외 (이번에 하지 않는다)

- 2~5단계 작업 전부 (학부모 리포트 화면, 판단 규칙 통일, 조교 오늘 수업 제한, 나머지 티켓 묶음, 화면 재구성)

- 디자인 변경: 색·폰트·배치는 위 항목에 필요한 만큼만 손댐
- 1단계 진행 중 새로 발견한 문제 → **고치지 않고 목록에만 기록** (6장 참고)

## 4. 완료 기준

### 4-1. 자동 점검 (전부 통과해야 완료)

`index.html#test` 콘솔에 **`SELFTEST PASS 15`** 가 나와야 한다.

| 작업 | 점검 이름 |
|---|---|
| 0 | 데이터 생성 |
| 1 | 버튼 두 번 눌러도 선택 유지 · 숙제 버튼 4번 누르면 빈칸 복귀 · 작성 중 케어 창 감지 · 모두 보류는 확인 거절 시 유지 · 점수 보정 |
| 2 | 동명이인 구분 · 연락처 권한 · 기준값 범위 · 원장 티켓 버튼 · 상담 요약 텍스트 |
| 3 | 초안에 부정어 없음 · 초안에 원본 문장 없음 |
| 4 | 기간 필터가 케어 카드에 반영 · 리포트 월에 10월 포함 |

### 4-2. 기존 기능 유지 (회귀 점검)

이전에 되던 흐름이 그대로 되어야 한다. 작업자가 직접 실행해서 확인한다.

- [ ] 조교: 화목 7:00반 점수 입력·저장 → 나머지 제안 생성
- [ ] 담임: 내 반 홈에서 제안 확정 → 티켓 발행
- [ ] 조교: 오늘 나머지에서 결과 저장 → 미완 과제 이월
- [ ] 원장: 대시보드·위험 학생 → 타임라인 → 상담 요약 → 월말 리포트 이동
- [ ] 원어민: 대표작 저장
- [ ] 4개 역할 모든 메뉴를 열었을 때 콘솔 오류 0건

### 4-3. 원장 체험 확인 (의뢰인이 직접)

- [ ] 조교 카드에서 같은 버튼을 두 번 눌러도 색이 유지된다
- [ ] 동명이인(예: 윤채원 2명)이 조교 화면에서 구분된다
- [ ] 강서연 9월 리포트 초안에 "엎드려" 같은 표현이 없다
- [ ] 대시보드 기간을 "최근 30일"로 바꾸면 케어 기록 숫자가 바뀐다
- [ ] 관리·설정에서 통과 기준에 0을 넣으면 거부된다

## 5. 작업 방식과 안전장치

- **순서 고정:** 0 → 1 → 2 → 3 → 4. 앞 작업의 점검이 통과해야 다음으로 넘어간다.
- **작업마다:** 점검 먼저 작성 → 실패 확인 → 수정 → 통과 확인 → git 저장.
- **되돌리기:** 문제가 생기면 해당 작업의 git 저장 직전으로 되돌린다. 의뢰인이 요청하면 1단계 전체를 작업 0 직후 상태로 되돌릴 수 있다.
- **수정 범위 제한:** 각 작업은 계획서에 적힌 함수만 고친다. 다른 함수를 고쳐야 하면 완료 보고에 이유를 적는다.
- **검토:** 작업 4까지 끝나면 별도 점검자가 1단계 전체 변경을 한 번 검토한다. 작업자가 스스로 승인하지 않는다.

## 6. 변경 관리

- 작업 중 새 문제를 발견하면 **고치지 않고** 완료 보고의 「발견 목록」에 적는다. 2단계 이후 계획에 넣을지는 의뢰인이 정한다.
- 단, 이번 작업 때문에 **새로 생긴 오류**는 1단계 안에서 고친다.
- 의뢰인이 범위 추가를 요청하면 이 계약서 2-1에 줄을 추가하고 4-1 점검도 함께 추가한 뒤 진행한다.

## 7. 중단 조건과 보고

**즉시 멈추고 의뢰인에게 묻는 경우**
- 같은 점검이 수정 3번 뒤에도 실패할 때
- 계획서대로 하면 기존 기능이 깨지는 것이 확인될 때
- 계획서에 없는 판단(문구, 숫자 기준 등)이 필요할 때

**완료 보고 형식**
1. 자동 점검 결과 (`SELFTEST PASS n` 원문)
2. 회귀 점검 체크리스트 결과
3. 작업별 변경 요약 (한 줄씩)
4. 계획과 달라진 점과 이유
5. 발견 목록 (고치지 않은 새 문제)
6. 원장 체험 확인 체크리스트 (4-3)

## 8. 위험과 대응

| 위험 | 가능성 | 대응 |
|---|---|---|
| 확인창(`confirm`)이 브라우저 미리보기에서 막혀 자동 점검이 멈춤 | 중간 | 점검 중에는 `confirm`을 가짜 함수로 바꿔 실행하고, 끝나면 원래대로 복구 |
| 기간 필터 변경이 다른 요약 카드 숫자까지 바꿈 | 낮음 | "기간 내 케어 기록" 카드만 바꾸고, 회귀 점검에서 나머지 카드 숫자를 이전과 비교 |
| 리포트 문장 템플릿이 어색해짐 | 중간 | 문장은 계획서에 고정된 문구만 사용. 다듬기는 원장 체험 후 별도 요청으로 |
| 동명이인 표시로 카드 제목이 길어짐 | 낮음 | 이름 · 학년 · 반 글자만 표시, 좁은 화면에서 줄바꿈 확인 |
| 새로고침 경고가 체험을 방해함 | 낮음 | 데이터를 실제로 바꾼 뒤에만 경고 |
