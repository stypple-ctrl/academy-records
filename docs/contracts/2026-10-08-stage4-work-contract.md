# 작업계약서 · 4단계 「나머지 티켓 묶음」 (위험 높음)

| 항목 | 내용 |
|---|---|
| 대상 파일 | `index.html` |
| 근거 | 작업 계획서 Task 7·8·9 + 재점검 반영 (2026-10-08) |
| 선행 조건 | 3단계 완료 (`SELFTEST PASS 61`, GitHub 업로드) |
| 승인 | 의뢰인 사전 승인 ("작업계약서에 따라 남은작업 순차진행", 2026-10-08) |
| 진행 | Task 7 → 8 → 9 순서 고정 (모두 나머지 티켓·기록 데이터를 건드림) → 별도 검토 → 전체 흐름 재점검 → GitHub |

## 1. 목적
실수해도 되돌릴 수 있고, 실제와 다른 기록이 남지 않게 한다.

## 2. 범위

| 번호 | 작업 | 내용 |
|---|---|---|
| **4-1** | 과제별 결과 (Task 7) | 조교 카드에서 **과제마다** 완료/부분/미완을 따로 고름 + "모두 완료" 버튼. 미완·부분인 과제만 다음 회차로 이월. 소요 시간·태도는 학생당 한 번 |
| **4-2** | 오늘 결과 되돌리기 (Task 7) | "오늘 처리 결과"에서 학생별 [되돌리기] (조교만): 오늘 기록 삭제 → 과제 다시 대기 → 오늘 만든 이월 과제 삭제 |
| **4-3** | 점수 정정 시 티켓 정리 (Task 8) | 점수를 고쳐서 통과가 되면 그 수업에서 나온, 아직 처리 안 한 "단어 재시험" 티켓을 취소. 여전히 미달이면 티켓 이름의 점수를 새 값으로. 숙제 X를 고치면 해당 숙제 티켓 취소. 맞지 않게 된 확정 대기 제안도 정리 |
| **4-4** | 티켓 취소 (Task 8) | 담임(자기 학생)·원장이 대기 중인 티켓을 [취소]. 이미 처리된 티켓은 취소 불가 |
| **4-5** | 케어 기록 수정·삭제 (Task 9) | 작성자 본인이 수정 가능, 이전 내용은 이력으로 보존("수정됨" 표시). 삭제는 **오늘 쓴 기록 + 결과 미입력**일 때만 |

### 재점검으로 바뀐 점
- 결과 고르기가 지금은 학생당 1개라서 과제별로 바꾸고 "모두 완료" 추가.
- 계획 이후 생긴 "결과 입력 대기 → 한 번에 결과 입력"(quickResult)과 퇴원 위험 처리 상태 자동 갱신은 그대로 동작해야 함. 수정은 새 기록으로 세지 않음(처리 상태를 다시 바꾸지 않음).

### 제외
5단계(셔틀 정렬, 교사 "오늘 메모"), 결정 대기 항목, DB 단계, 발견 목록의 작은 문제.

## 3. 완료 기준

### 자동 점검: `SELFTEST PASS 67` (61 + 6)
| 점검 | 내용 |
|---|---|
| 과제별 결과·부분 이월 | 과제 2개 중 하나 완료·하나 미완 → 미완만 이월, 학기 미완 +1 |
| 오늘 결과 되돌리기 | 되돌리면 과제 다시 대기, 이월 과제·오늘 기록 삭제 |
| 점수 정정 시 재시험 티켓 취소 | 20점 → 26점으로 고치면 그 수업 재시험 티켓이 대기 명단에서 사라짐 |
| 처리된 티켓은 취소 불가 | 기록이 있는 티켓 취소 시도 → 거부 |
| 케어 수정 이력 | 수정하면 내용이 바뀌고 이전 값 1건 보존, 기록 수는 그대로 |
| 지난 기록 삭제 불가 | 어제 이전 기록 삭제 시도 → 거부 |

### 기존 기능 유지 (4단계 끝나고 처음부터 다시)
조교 입력 → 담임 확정 → 조교 처리(과제별)·이월 → 원장 브리핑·위험 학생 → 타임라인·상담 준비 → 월말 리포트·학부모 화면 → 원어민 대표작, 전 메뉴 오류 0건.

### 원장 체험 확인
- [ ] 조교 카드에서 과제 2개 중 하나만 "완료", 하나는 "미완"으로 저장하면 미완만 내일로 넘어간다
- [ ] "오늘 처리 결과"의 [되돌리기]를 누르면 학생 카드가 다시 생긴다
- [ ] 조교가 20점으로 입력해서 생긴 재시험이, 26점으로 고치면 사라진다
- [ ] 담임이 케어 기록을 고치면 타임라인에 "수정됨"이 붙는다
