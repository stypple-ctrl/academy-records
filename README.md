# 학원 통합 기록관리 시스템 · 체험용 데모

원장·교사·조교가 학생 기록을 한 곳에 쌓고, 각자 필요한 화면으로 보는 **영어학원용 기록관리 웹앱**입니다.
쌓인 기록은 학부모 월간 리포트와 상담 자료로 이어집니다.

> ⚠️ **지금은 체험용 데모입니다.** 학생·점수·기록 데이터는 모두 임의로 만든 가짜이고, 오늘 날짜는 2026-10-01로 고정되어 있습니다. 새로고침하면 처음 상태로 돌아갑니다.

---

## 목표

PRD(2026-10-01)의 네 가지 목표를 기준으로 합니다.

1. **학부모 신뢰:** "학원이 우리 아이를 알고, 먼저 발견해서 챙기고, 성장시켰다"는 증거를 매달 보여준다.
2. **성과:** 기록이 다음 수업의 행동(누구를, 무엇을 챙길지)으로 바로 이어진다.
3. **교사 부담 최소화:** 수업 중 추가 업무 0, 교사 1인당 하루 입력 10분 이내.
4. **원장 가시성:** 교사·반·학년·학교·기간별 기록을 클릭 한 번으로 본다.

## 진행 방식

1. **데모로 체험** → 원장 피드백 → 데모 수정 (지금 여기)
2. 데모가 괜찮아지면 **실제 프로그램으로 전환** (Next.js + Supabase + Vercel, DB 연결·로그인·권한)
3. 교사 1명·1~2개 반으로 **4주 시범 운영**

### 역할별 새 방향 (2026-10-08 원장 피드백 → 구현 완료)
역할별로 "기록 도구"에서 "놓치기 전에 알려주는 도구"로:
- **원장:** 출근하면 켜 두는 아침 브리핑 — 퇴원 위험, 신규생 적응, 반별 상태, 선생님별 "놓치고 있는 것"
- **교사:** 입력 최소화(자동 초안), 상담 준비 카드(대화 문장까지), 퇴원 위험 조기 알림 + 챙긴 기록
- **조교(주 2회 출근):** "지난 출근 이후" 요약, 학생별 "오늘 시킬 것" 지시 카드, 틀린 번호만 누르는 자동 채점
- 필요한 새 데이터: 등록일·퇴원일·퇴원 사유, 담임→조교 당부, 단어 시험 정답지·문항별 오답, 위험 학생 처리 상태, 조교 출근 기록

### 원장 결정이 필요한 것 (PRD 10장 미결)
- [ ] 학부모 연락 수단(문자/알림톡)과 문구 승인 절차
- [ ] 월말 리포트 발송 주체와 일정 (담임 검토 → 원장 승인 → 발송)
- [ ] 원어민 교사 인원과 원어민 반 편성, 원어민 숙제 입력 위치
- [ ] 강당 조교가 쓸 기기 (강당 PC 유무)
- [ ] 반 이동·휴원·학기 전환 처리
- [ ] 학원 이름 (지금은 "OO영어학원")
- [x] 퇴원 위험 신호·신규생 8주·선생님별 현황 원장만·틀린 번호 채점 (추천값으로 확정, 관리·설정에서 조정)
- [ ] 퇴원 위험 점수 가중치를 시범 운영 데이터로 다시 맞추기

### 실제 프로그램 전환 때 할 것
로그인과 역할별 접근 제한(RLS), 수정 이력 저장, 저장 실패 재시도, 퇴사 조교 계정 차단, 자동 백업, 교사 입력 시간 측정, AI 상담 요약·리포트 코멘트(Claude API)

> 실제 학생 데이터나 DB 접속 정보를 쓰기 전에 이 저장소를 **비공개로 전환**해야 합니다.

### 아직 고치지 않은 작은 문제 (발견 목록)
6단계(2026-10-08)에서 이전 목록 약 30건을 정리했습니다. 남은 것:
- (6단계 최악의 데이터) 여러 줄로 감긴 메모·당부 옆의 배지·이름이 세로 가운데에 떠 보임 (위쪽 정렬 권장)
- (6단계) 할 일 목록의 숨긴 항목 계산이 화면을 그릴 때마다 반복됨 (학생 수가 많아지면 느려질 수 있음)
- (6단계 검토) 표의 행 전체가 '버튼'으로 읽힘(화면 낭독기), 1분마다 화면을 다시 그릴 때·입력 창 칩을 누를 때 키보드 위치가 처음으로 돌아감
- (7단계 검토) 사이드바 «·표/보드 전환·보드 상태 바꾸기를 누르면 화면을 다시 그리면서 키보드 위치가 처음으로 돌아감
- (6단계 검토) 담임 '오늘 챙길 학생'의 미달 2회 신호에는 4주 기간 제한이 아직 없음, 결석으로 다시 저장한 학생의 관찰 태그가 남음, 다른 조교가 처리한 줄에도 되돌리기 버튼이 보임(눌러도 동작 안 함)
- 데모 날짜가 10/1(목)로 고정이라 셔틀 "N분 남음"은 실제 시계를 씀 (실제 프로그램에서 해결)
- 개발용 데이터 전환: 주소 끝에 `?data=worst` 또는 `?data=empty` → 화면 아래에 "데모 데이터 / 최악의 경우 / 비어 있음" 전환 버튼

## 배포 (Vercel)
- 공개 주소: **https://academy-records.vercel.app** (주소를 아는 사람은 누구나 볼 수 있음, 데이터는 모두 가짜)
- 배포 명령: `npx vercel@latest deploy --prod --yes`. 원장이 "배포해"라고 하면 자동 점검 통과 후 실행함
- 올라가는 파일은 `index.html` 하나뿐 (`.vercelignore`). GitHub에 올려도 자동 배포는 되지 않음
- ⚠️ 실제 학생 데이터나 DB 접속 정보를 넣는 단계가 오면, 배포 전에 접근 제한(비밀번호 보호 등)을 먼저 정함

## 학교 정보 연동 (8단계)
- 학생의 학교 이름을 누르면 그 학교의 **학사일정(NEIS)**과 **학생 수·학급 현황(학교알리미)**이 뜹니다. 원장 아침 브리핑에는 **다가오는 학교 시험**(실제 오늘 기준 45일 안)이 나옵니다.
- 키는 버셀 Production 환경 변수 `NEIS_KEY`, `SCHOOLINFO_KEY`에만 있습니다. 코드와 GitHub에는 없습니다.
- 서버 함수 `api/school.mjs`가 중계합니다. 정해 둔 학교 5곳(안산 단원구 고잔초·와동초·선부초·단원중·와동중)만 조회하고, 응답은 6시간 저장해 다시 씁니다.
- **배포 주소에서만 동작합니다.** 내 컴퓨터에서 파일로 열면 "배포 주소에서만 불러옵니다"가 뜹니다.
- 점검: `node tests/api-school.test.mjs` (GitHub에 올릴 때 자동으로 같이 돕니다)

설치할 것 없습니다. `index.html`을 브라우저로 열면 됩니다.

### 자동 점검

```bash

```

## 기술

HTML 파일 하나(인라인 CSS + 바닐라 JavaScript), 외부 라이브러리 없음(글꼴 Pretendard만 CDN).
